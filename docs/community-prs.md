## Черновик issue про веб-панель

```
Заголовок: Веб-панель как опциональный extra [panel]?

Привет! Я сделал для себя веб-панель к утилите и хочу понять, интересно ли это в основном репозитории, прежде чем присылать код.

Что умеет:
- запуск любых команд утилиты из браузера с живым выводом, очередь задач;
- расписание (по времени, по интервалу, "поднимать резюме, как только hh разрешит");
- поиск вакансий с проверкой AI-фильтром и правкой письма перед откликом;
- отклики и чаты: черновик ответа от модели, отправляете вы;
- журнал решений AI с промптами и ответами;
- редактор config.toml и промптов, управление локальными моделями Ollama.

Как устроено: только стандартная библиотека Python (http.server, threading), фронтенд на чистом JS без сборки. Команды утилиты запускаются отдельными процессами, панель вызывает операции через подклассы, без правок существующего кода. По умолчанию слушает только 127.0.0.1. Снаружи вход по токену, cookie HttpOnly/SameSite=Strict, строгий CSP, изменяющие запросы только с заголовком X-Panel-Request.

Объём около 6 тысяч строк, поэтому предлагаю, если интересно, присылать частями: сервер и очередь задач -> экраны -> расписание -> чаты.

Если в основной репозиторий не нужно, оформлю отдельным пакетом hh-applicant-panel, который зависит от hh-applicant-tool. Тогда вопрос только в том, можно ли сделать публичными несколько методов операций (проверка одной вакансии без отклика, загрузка данных чата), чтобы пакет не лез во внутренности.
```

Скриншоты для issue снимать с мок-стенда, где нет личных данных: экраны обзора, вакансий, чатов, расписания.
